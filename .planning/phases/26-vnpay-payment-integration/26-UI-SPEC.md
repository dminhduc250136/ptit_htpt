# Phase 26 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase:** Tích Hợp Thanh Toán VNPay Sandbox
**Frontend surface (NHỎ — bám sát design system có sẵn, tái dụng tối đa, KHÔNG sáng tạo pattern mới):**

1. **Checkout payment method selector** — thêm option `VNPAY` vào radio selector tại `sources/frontend/src/app/checkout/page.tsx` (hiện có `COD | BANK_TRANSFER | E_WALLET`). Chọn VNPay + đặt hàng → `window.location` redirect sang `paymentUrl` (D-14).
2. **Trang kết quả thanh toán** — route mới (return URL VNPay trỏ về), 3 trạng thái thành công / thất bại / huỷ; render sơ bộ từ `vnp_ResponseCode` → POLL `payment_status` của đơn chờ IPN xác nhận (D-12, D-13). Hiển thị "đang xác nhận" trong lúc poll.
3. **Order display** (`/profile/orders/[id]` + `/admin/orders/[id]`) — chỉ thêm hiển thị `payment_status` / method `VNPAY` / mã giao dịch VNPay. Tái dụng `paymentStatusMap` / `paymentMethodMap` (`src/lib/orderLabels.ts`) — KHÔNG thiết kế mới.

| Role | Size | Weight | Line Height | Token |

## Color

Bảng 60/30/10 ánh xạ token "The Digital Atélier" đã tồn tại — Phase 26 KHÔNG thêm màu mới.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f7f9fb` (`--background` / `--surface`) | Nền trang checkout + trang kết quả |
| Secondary (30%) | `#ffffff` (`--surface-container-lowest`) / `#eceef0` (`--surface-container`) | Card form section, card kết quả thanh toán, radio option surface |
| Accent (10%) | `#0056d2` (`--primary-container` / `--brand-primary`) | Xem danh sách reserved bên dưới |
| Destructive | `#ba1a1a` (`--error`) | Trạng thái thất bại / huỷ thanh toán, thông báo lỗi |

**Accent reserved for (danh sách tường minh — KHÔNG dùng accent cho mọi phần tử tương tác):**
- Primary CTA button trên trang kết quả ("Xem đơn hàng" / "Thử lại thanh toán")
- Viền + nền nhạt của radio option VNPay khi được chọn (`styles.paymentActive` — reuse pattern hiện có)
- Nhãn `payment_status` khi trạng thái = "Đã thanh toán" (đã có `styles.paymentStatus { color: var(--primary) }`)

**Semantic màu cho 3 trạng thái trang kết quả + Badge order display:**

| Trạng thái | Màu / Badge variant | Token |
|-----------|---------------------|-------|
| Thành công (PAID) | xanh thành công | `Badge variant="sale"` (precedent `statusMap.DELIVERED`) — KHÔNG dùng accent xanh primary để tránh nhầm CTA |
| Đang xác nhận (PENDING, đang poll) | trung tính | `--on-surface-variant` text + spinner; `Badge variant="default"` |
| Thất bại (FAILED) | đỏ destructive | `--error` / `--error-container`; `Badge variant="out-of-stock"` |
| Huỷ (user huỷ tại cổng) | trung tính cảnh báo | `--on-surface-variant`; `Badge variant="default"` |

## Interaction Contract — Trang kết quả thanh toán (D-13 polling)

| Khía cạnh | Quy định |
|-----------|----------|
| Render sơ bộ | Đọc `vnp_ResponseCode` từ query string ngay khi mount: `00` → giả định thành công (chờ IPN), `24` → huỷ, còn lại → thất bại |
| Nguồn sự thật | `payment_status` của đơn (GET order) — return URL CHỈ để hiển thị sơ bộ (D-06) |
| Polling | Sau render sơ bộ, poll `GET /api/orders/{id}` mỗi **3 giây**, tối đa **5 lần** (~15s tổng). Dừng sớm khi `payment_status` ≠ `PENDING` |
| UI trong lúc poll | Hiển thị state "Đang xác nhận thanh toán" + spinner; KHÔNG hiển thị kết quả cuối cho tới khi poll kết thúc hoặc trạng thái terminal |
| Poll hết hạn | Vẫn `PENDING` sau 5 lần → hiển thị copy "Chưa nhận được xác nhận" (không phải lỗi cứng) |
| Lỗi mạng khi poll | Reuse `RetrySection` — nút thử lại poll thủ công |
