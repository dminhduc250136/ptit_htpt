<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → user-service | Request đăng ký / forgot / reset từ internet (qua gateway) |
| verification_tokens table | Token xác minh/reset là secret — leak = chiếm tài khoản |
| user-service → RabbitMQ | UserPayload mang email + actionUrl (chứa token) qua broker |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-03 | Spoofing/Elevation | Token reset đoán được → chiếm tài khoản | mitigate | Token = SecureRandom 32 byte (256-bit entropy) base64url — không brute-force khả thi (D-06). |
| T-27-04 | Replay | Token reset/verify dùng lại nhiều lần | mitigate | verifyAndConsume dùng SELECT FOR UPDATE + check used_at IS NULL + set used_at trong cùng transaction (Pitfall 4). |
| T-27-05 | Information Disclosure | Token hết hạn vẫn dùng được | mitigate | verifyAndConsume check expires_at > now(); TTL EMAIL_VERIFY 24h, PASSWORD_RESET 1h (D-06). |
| T-27-06 | Information Disclosure | actionUrl chứa token đi qua broker | accept | Broker docker network nội bộ; token đằng nào cũng phải gửi tới email khách. |
</threat_model>
