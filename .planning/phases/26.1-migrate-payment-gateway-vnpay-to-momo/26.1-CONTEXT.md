<decisions>
## Implementation Decisions

### Cổng thanh toán mới
- **D-01:** Dùng **MoMo Developer Sandbox** (`developers.momo.vn`). Lý do: sandbox key có sẵn PUBLIC trong doc — không cần KYC/đăng ký phức tạp như VNPay; HMAC SHA256 đơn giản hơn SHA512 URL-encoding của VNPay; API JSON REST thay vì query string ký.
- **D-02:** Dùng API "One-time payment" (`/v2/gateway/api/create`) — phổ biến nhất, hỗ trợ payUrl redirect + IPN.

### Service ownership (giữ y nguyên Phase 26)
- **D-03:** `payment-service` sở hữu toàn bộ logic MoMo: build payment URL (POST sang MoMo create endpoint), verify chữ ký HMAC SHA256, nhận return + IPN callback, idempotency. `order-service` KHÔNG implement payment callback.
- **D-04:** `order-service` vẫn gọi REST đồng bộ sang `payment-service` `POST /payments/sessions` (provider="MOMO") để nhận `paymentUrl` (giữ nguyên `PaymentSessionClient`).
- **D-05:** `payment-service` phát event RabbitMQ `PaymentSucceeded`/`PaymentFailed` (exchange `payment.events` đã có). `order-service` `PaymentEventListener` consume không đổi — payment_status cập nhật giống hệt VNPay flow.

### Strategy migration: replace (không generalize)
- **D-06:** **Xóa sạch package `paymentservice/vnpay/`** + 2 file test (VNPaySignatureTest, VNPayIpnControllerIT). KHÔNG refactor thành interface `PaymentProvider` với 2 implementation. Lý do: KISS, project demo GSD workflow ưu tiên đơn giản; nếu sau cần multi-gateway sẽ làm phase riêng.
- **D-07:** **Rename cột DB** `vnp_transaction_no` → `payment_transaction_no` qua Flyway V7 migration. Cột này dùng chung cho mọi gateway (giờ là MoMo, tương lai có thể khác). Rename luôn ở `OrderEntity`, `OrderDto`, `OrderMapper`, FE types.
- **D-08:** **Enum value đổi** `VNPAY` → `MOMO` trong `OrderEntity.paymentMethod` + FE `orderLabels.paymentMethodMap` + FE checkout selector + `OrderCrudService.createOrderFromCommand` switch case. Order COD/BANK_TRANSFER/E_WALLET không đổi.
- **D-09:** **Không migrate dữ liệu cũ:** đơn VNPAY đã tạo trong test Phase 26 (nếu có) bị orphan — chỉ có vài đơn test, chấp nhận `paymentMethod='VNPAY'` lưu trong DB legacy. KHÔNG viết script migrate enum value cũ.

### MoMo signature & flow
- **D-10:** HMAC SHA256 ký format string MoMo quy định (concatenated key=value với `&` separator, KHÔNG sort, KHÔNG URL-encode). Theo doc MoMo: `accessKey=...&amount=...&extraData=...&ipnUrl=...&orderId=...&orderInfo=...&partnerCode=...&redirectUrl=...&requestId=...&requestType=...`.
- **D-11:** `requestId` (idempotency key của MoMo) = `paymentSessionId` (giữ pattern như VNPay's `vnp_TxnRef` mapping). `orderId` của MoMo = `paymentSessionId` (MoMo yêu cầu unique). `extraData` mang `orderId` của hệ thống để liên kết khi IPN về.
- **D-12:** IPN endpoint nhận POST JSON từ MoMo. Response format: HTTP 204 No Content (hoặc JSON `{}`). Khác VNPay là GET với query + JSON response.

### Endpoints
- **D-13:** Đổi endpoint URL: `/payments/vnpay/return` → `/payments/momo/return` (GET, browser redirect), `/payments/vnpay/ipn` → `/payments/momo/ipn` (POST JSON, server-to-server). `ApiResponseAdvice` skip prefix update từ `vnpay` → `momo`.
- **D-14:** Gateway whitelist (Phase 25 public-endpoint list) đổi từ `/api/payments/vnpay/**` → `/api/payments/momo/**`.

### Frontend
- **D-15:** `/checkout` selector: thay text "Thanh toán qua VNPay" → "Thanh toán qua MoMo", icon emoji 💳 → 📱 (hoặc giữ 💳 cũng được). Value enum đổi `VNPAY` → `MOMO`.
- **D-16:** Trang `/checkout/result` giữ NGUYÊN logic (resolve orderId → poll payment_status 3s×5 → 5 trạng thái). Chỉ đổi `getVNPayReturn` → `getMomoReturn`, endpoint `/api/payments/vnpay/return` → `/api/payments/momo/return`. Copy strings UI-SPEC giữ nguyên (chung cho mọi gateway).
- **D-17:** Order display tại `/profile/orders/[id]` + `/admin/orders/[id]`: đổi label hiển thị "Mã giao dịch VNPay" → "Mã giao dịch MoMo". Field rename `vnpTransactionNo` → `paymentTransactionNo`.

### Configuration
- **D-18:** Env vars MoMo (set trong `.env` ở root):
  - `MOMO_PARTNER_CODE` (sandbox public: `MOMO`)
  - `MOMO_ACCESS_KEY` (sandbox public: `F8BBA842ECF85`)
  - `MOMO_SECRET_KEY` (sandbox public: `K951B6PE1waDMi640xX08PD3vg6EkVlz`)
  - `MOMO_PAY_URL` (default `https://test-payment.momo.vn/v2/gateway/api/create`)
  - `MOMO_RETURN_URL` (default `http://localhost:3000/checkout/result`)
  - `MOMO_IPN_URL` (default trống — cần khi có tunnel ngrok cho IPN)
- **D-19:** docker-compose `payment-service` env: xóa block `VNP_*`, thêm block `MOMO_*`. Cập nhật `.env.example` (nếu có).

### Tests
- **D-20:** Tạo `MomoSignatureTest` (unit test HMAC SHA256 round-trip + reject tampered) + `MomoIpnControllerIT` (integration test verify chữ ký + amount check + idempotent). Xóa file VNPay test cũ.
- **D-21:** Cập nhật `OrderCrudServiceVNPayIT` → `OrderCrudServiceMomoIT` (đổi method enum), `PaymentEventListenerIT` giữ nguyên (đã test event shape chung). Update Playwright `12-vnpay-payment.spec.ts` → `12-momo-payment.spec.ts` (đổi text "Thanh toán qua MoMo", endpoint mock).

- Cách handle `extraData` field của MoMo (Base64 JSON encoded — chứa orderId nội bộ).
- Icon emoji checkout option (📱 / 💳) — UI-SPEC researcher chốt.
- Whether to delete legacy Phase 26 SUMMARY/PLAN/VERIFICATION/HUMAN-UAT artifacts (giữ làm history; chỉ xóa source code VNPay).
- Cách xử lý đơn legacy có `paymentMethod='VNPAY'` (chấp nhận orphan; FE render fallback "Thanh toán qua VNPay (đã ngừng)" nếu hiển thị).
