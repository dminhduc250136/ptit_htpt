# Phase 24 — Plan 02: application.yml + bỏ default_schema + grep audit

**Phase:** 24
**Plan:** 02 of 04
**Depends on:** 24-01

## Goal

Mỗi backend service trỏ DB target riêng theo Plan 01, bỏ `default_schema: <svc>_svc` trong cả `jpa.properties.hibernate.default_schema` và `flyway.default-schema`. Audit grep mọi reference `<svc>_svc.<table>` và refactor sang non-prefixed (dùng schema `public`).

Reference: 24-CONTEXT.md D-06, D-07, D-10, D-14 (error contract), D-15 (Hikari config).

## Tasks

### T-24-02-01: application.yml cho 5 service (user/product/order/inventory/payment)

Mỗi file `sources/backend/<svc>/src/main/resources/application.yml`:
- Đổi `spring.datasource.url` (nếu hardcode) → dùng env `jdbc:postgresql://${DB_HOST}:${DB_PORT}/${DB_NAME}`. Nếu đã env-driven thì OK.
- XÓA dòng `default_schema: <svc>_svc` (cả 2 chỗ: jpa.properties.hibernate + flyway).
- Thêm `spring.datasource.hikari.initialization-fail-timeout: -1` (D-15 — cho phép start khi DB chưa lên).
- (Nếu chưa có) thêm `spring.flyway.locations: classpath:db/migration` để rõ ràng. Profile `dev` đã có `classpath:db/seed-dev` → giữ.

### T-24-02-02: Refactor schema-prefix trong Java + SQL

- Chạy `grep -rn "user_svc\.\|product_svc\.\|order_svc\.\|inventory_svc\.\|payment_svc\.\|notification_svc\." sources/backend/` — list tất cả match.
- Cho mỗi match:
  - **Flyway `.sql`**: xóa prefix `<svc>_svc.` khỏi `CREATE TABLE`, `ALTER TABLE`, `INSERT INTO`, FK references. Bỏ `CREATE SCHEMA IF NOT EXISTS <svc>_svc` nếu có.
  - **Native query `@Query(value="...", nativeQuery=true)`**: xóa prefix.
  - **JPA `@Table(schema="<svc>_svc")`**: xóa attribute `schema`.
- Đặc biệt chú ý nếu Phase 23 đã merge: `inventory_svc.processed_events`, `inventory_svc.stock_ledger`, `notification_svc.dispatch_log`, `notification_svc.processed_events`.

### T-24-02-03: Update Testcontainers integration tests

- `grep -rn "Testcontainers\|PostgreSQLContainer" sources/backend/` — list.
- Mỗi test class: container start `postgres:16-alpine` riêng → KHÔNG cần config schema (dùng `public` mặc định). Nếu code test setup có `CREATE SCHEMA` hoặc set `default_schema` → xóa.
- Run `./mvnw -pl <svc> test` (hoặc `mvn -pl ...`) cho từng service → đảm bảo green.

### T-24-02-04: Smoke runtime

- `docker compose up -d --build` → đợi healthcheck.
- `curl http://localhost:8080/api/products?page=0&size=5` → 200, có data seed.
- `curl http://localhost:8080/api/users/auth/login` với credential admin seed → 200, có JWT.
- `docker exec postgres-product psql -U product_svc -d product_svc -c "\dt"` → liệt kê bảng trong `public` schema, KHÔNG có `product_svc` schema.

## Acceptance

- Mọi `application.yml` backend service không còn `default_schema`.
- `grep -rn "_svc\." sources/backend/` chỉ trả result trong comment/docs, không trong SQL/Java code thực thi.
- 6 service `./mvnw test` green.
- Smoke endpoints catalog + auth hoạt động.
